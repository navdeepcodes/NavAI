Mike doesn't need a window

A redesign of how Mike exists on the machine — three visual languages, one recommendation, and a diagnosis of why the current Home reads as a chatbot with the lights off.

Substrate frozen Backend untouched Qwen3 8B · local PySide6 · QPainter
00

What Home V1 actually taught us

Before proposing anything, here is the current build rendered at full size. Not from memory — captured from the running widget tree.

The problem is not the palette. Both frames are structurally a chatbot empty-state: centred avatar, greeting, pill composer, three-link footer. Nine specific faults:

  • The composition is the ChatGPT/Siri empty state. Centred mark, greeting, rounded input, footer links. Reordering the pixels won't change what it's a copy of.
  • The orb is the most-taken mark in software. Concentric arcs with a bloom is Siri, Copilot, Gemini, and forty startups. It also reads as a spinner, which means "wait", not "intelligence".
  • Roughly 55% of the frame is unresourced black. That isn't restraint. Restraint is space doing work; this is space nothing was put in.
  • The greeting occupies the most valuable position on screen and says nothing. "Good afternoon. / Ready when you are." is two lines of filler in the optical centre.
  • The brightest object is the send button. A saturated blue circle out-shouts Mike himself, to submit a form.
  • Activity is a dashboard card. Grey rounded rectangle, green ticks, centred Stop. This is the component library talking, not the product.
  • Nothing distinguishes what Mike said from what Mike did. One typeface, one register, so a claim and a fact look identical — a real honesty problem given the known narration limitation.
  • Nothing on screen belongs to this computer. No path, no project, no editor, no moment. It would look the same on any machine, which is the opposite of the pitch.
  • The frontmost-app readout says "ChatGPT". Mike's own UI is quietly captioning its problem in the top-right corner.

The real fault

Every one of those is downstream of a single decision: Mike was built as a place you go. Repainting a destination still leaves a destination. The rest of this document changes the model, not the paint.

01

One product, five depths

Mike's primary surface is not a window. Depth is chosen by what the user needs, never by what the interface wants to show.

D0AmbientRunning, listening for the wake word, holding situation. Zero pixels. The default state, and where Mike spends 99% of its life.
D1EdgeA temporary opening at the screen edge. Answers, acts, asks, disappears. Never takes focus. The most important surface in the product.
D2InvocationSummoned deliberately by shortcut or wake word. A single line that accepts typing. Takes focus because the user asked for it.
D3HomeWhere you dwell: review, memory, record, settings. Opened a few times a week, not a few times an hour.
D4EmbeddedInside the editor. Same identity at gutter scale. Future — the bridge exists, the presence does not.

The escalation rule: Mike may deepen only on user action. A D1 answer never promotes itself to D2. Work started at D1 finishes at D1. If the answer is too big for the edge, the edge says so and offers the escalation — it does not perform it.

Why four and not seventeen. The brief's list is a feature inventory. Users don't arrive with features in mind; they arrive with a question. Record answers "what happened", Mind answers "what do you know", Conduct answers "how do you behave and what can you touch", and Now is where they already are. Anything that fits none of these is a feature we haven't justified.

Library folds into Record because an artefact without the action that produced it is orphaned — you look for "the site you built me on Tuesday", not for a file. Projects and Schedules live in Mind, not Record, because they are things Mike holds, not things Mike did.

Capability honesty

Green live is backed by code that exists today — brain/activity_store.py, brain/memory_store.py, brain/situation_store.py, memory/, the safety gate, the VS Code bridge. Amber later has no backing store and must not be drawn as a working surface. Designing the room is fine; shipping an empty room with buttons is not.

03

Three visual languages

Not three palettes. Three different answers to "what is Mike, visually" — spatial, typographic, luminous. Each specimen below shows the same moment: Mike working at the screen edge while you use another app.

04

Recommendation

CARET

Mike is the place the machine is paying attention. Everything else on screen is greyscale text.

  1. It is genuinely unclaimed. Orbs, waveforms and blooms are taken by every assistant shipping today. No AI product uses the caret as its identity, and it is the one symbol that is native to computing rather than borrowed from science fiction.
  2. It promises the right thing. A caret means attention and a place to act — not autonomy. Given the measured Qwen3 8B narration limitation, an identity that promises attentiveness rather than agency is the honest one. An orb implies a mind working alone; a caret implies a machine waiting with you.
  3. It survives every depth unchanged. 3px in the edge strip, in a VS Code gutter, in the menu bar; 34px at Home. SEAM cannot fill D3. CHAMBER cannot exist 3px wide. CARET is the only one that is the same object at D1 and D4.
  4. Qt renders it perfectly. A hard-edged rectangle and well-set text are exactly what QPainter is good at. Blur, bloom and large gradients are what it is bad at — and that gap is visibly why V1 looks cheap. This direction removes the failure mode instead of fighting it.
  5. It solves said-vs-did for free. The prose/mono split makes claims and facts typographically inseparable from their status, with no card, badge, icon or colour code. That is the honesty requirement met by the type system itself.
  6. It absorbs SEAM. SEAM's real contribution is behaviour — the edge as displaced geometry, growth along one axis, no floating panels. CARET takes that wholesale and supplies the identity SEAM lacks. This is composition, not hedging: SEAM gives the room its shape, CARET gives it its occupant.

CHAMBER is rejected on evidence, not taste. We built it, it is the thing in §00, and its failure was as much technical as conceptual. Reviving it would mean betting the identity on the one class of rendering our toolkit does worst.

Rules the edge must obey

Never accepts focus (WindowDoesNotAcceptFocus, already in the build). Never wider than 380pt or taller than 4 lines — past that it says ↩ open instead of growing. Anchors to the edge nearest the frontmost window's caret, not to a fixed corner. Auto-collapses 6s after a terminal state, but never while amber.

06

D2 · Invocation

⌘⇧Space or "Hey Mike" from anywhere. The distinction from D1 is intent: you asked, so Mike may take focus.

invoked · anywhere
Ask, or just talk ⌘⇧␣

How Mike enters. Not a window that fades in. The caret is drawn at the current mouse-or-focus point at full size, then the line unrolls sideways from it in 160ms. The caret is already blinking before the surface exists — Mike arrives first, the interface catches up. Dismiss reverses it: the line rolls back into the caret, the caret fades over 90ms.

One line, not a window. No title bar, no send button, no mic icon — Return submits, ⌘⇧Space or Esc dismisses, and holding the shortcut is push-to-talk. If a response is short it renders in place, under the line. If it isn't, the answer moves to the edge and the invocation closes, so Mike hands you back your screen.

No hero, no orb, no greeting, no cards, no sidebar. Home opens into the last exchange, because Mike is continuous — there is no empty state to fill with a salutation.

What carries the composition. A single left-aligned column on a baseline grid. The caret at top-left is Mike; it breathes when idle and is the only colour above the fold. Context sits in the top rail as machine facts, not as a badge — it names this computer, which is the thing V1 never did.

What is deliberately absent. No greeting (filler). No capability grid (a features page pretending to be a home). No orb (taken). No dashboard cards (the component library talking). No sidebar — the four rooms are four words on one line, because four destinations don't need furniture.

Rooms open as full-surface replacements, not panels. Home is a single column that changes contents; the caret stays put across the transition, so the room changes around Mike rather than Mike moving between rooms.

The three registers, and nothing else: user input sits dim behind a hairline rule; prose is what Mike said; mono behind a rule is what Mike observed or did. A reader can tell a claim from a fact without reading a word — which is precisely the protection needed against a model that sometimes narrates instead of acting.

Long conversations collapse by exchange, not by message: older exchanges compress to a one-line mono summary with their action count, expanding on click. Voice conversation is the same surface with the caret cyan and amplitude-driven; spoken replies stream into the prose register as they're synthesised, so reading and hearing stay in sync. Memory references are underlined inline and open the Mind row that produced them — a claim you can audit in one click. Continuation from D1/D2 appends to the same thread; there is one conversation, entered at different depths.

Failures and denials are first-class entries, rendered in the same weight as successes. A log that only shows wins is a marketing surface. Denials in particular are the user's own decisions and belong in the record.

Structural honesty. There is no row for an action that has not started, because Agency V2 genuinely cannot know the next step until the current tool returns. The current action is the last row and the only bright one; there is never anything beneath it. No progress bar, no step count, no percentage — all three would require knowing a total we do not have.

10

Mind · Memory

Prose you can read, not rows you administer. Each item is a sentence in Mike's voice, with its provenance in mono beneath it.

About you You work on a MacBook Air M4 with 16 GB of memory, and you care about everything staying local.learned 2 Sep · from conversation · referenced 6× edit · forget
Preference You want direct answers and you get annoyed when I hedge.learned 3 Sep · from correction · referenced 2× edit · forget
Work Mike itself lives at ~/Developer/NavAI-v0 and the backend is frozen.learned 1 Sep · from conversation · referenced 11× edit · forget

Why prose. A key/value table makes memory feel like a database you maintain; a sentence makes it feel like something Mike believes — which is what it is, and what makes a wrong one worth correcting. edit opens the sentence for direct editing. forget deletes immediately with a single undo, no confirmation dialog: hesitating to delete a memory is the wrong instinct to design in.

Provenance is the trust mechanism. When it was learned, where from, and how often it has actually been used. A memory referenced 11 times is load-bearing; one referenced zero times in a month is a candidate for forgetting, and Mind can say so.

11

Continuity surfaces — designed, not buildable

No backing store exists

Projects, Schedules and Library have no persistence today. They are designed here so the IA has room for them; each needs its own store before any of it is drawn in the app. Shipping an empty room with working-looking buttons is the exact dishonesty §08 of the brief forbids.

Projects

A persistent area of work: a root path, the memories scoped to it, and its slice of the Record. Not a project manager — Mike's answer to "we've been working on this for weeks". Entered by opening a folder Mike already knows, never by filling in a form. Needs: a project store keyed by path, plus memory scoping.

Schedules

Things Mike is expected to do at a time. Written as a sentence, kept as one line, and shown with the last actual outcome attached — a schedule that has never successfully run must say so on its own row. Needs: a scheduler, a durable queue, and a policy for confirmation gates when nobody is at the keyboard — the hardest of the three, because unattended agency and the safety gate are in direct tension.

Library

Not a folder. The artefacts Mike produced, each still attached to the action that produced it, so it is found by the story rather than the filename. Needs: artefact tracking on write/create tool calls.

Limits is deliberately not editable into unsafety. The confirmation gate has no off switch here — it is stated as a fact about Mike, not offered as a preference. Scope can be narrowed but the gate itself is architecture, and a settings screen that can disable it would be a second safety system by another name.

Privacy states rather than asks. "Everything stays on this Mac" with the evidence beneath it — no cloud endpoints, no analytics, no telemetry, model running locally at qwen3:8b. It is the product's strongest claim and it should read as a fact, not a toggle.

Every row is a signal that already exists in the frozen runtime. Nothing in this table requires a new backend event, and nothing animates on a timer that isn't tied to real work — an animation running while nothing happens is a lie told at 30fps.

Reduced motion (com.apple.universalaccess reduceMotion, already readable) drops all animation; state falls back to caret colour plus one mono word, and the interface loses nothing it needed.

What this design may never render

Progress bars. Step counts ("3 of 7"). Speculative future steps. "Mike is working autonomously." Completion language before a tool returns. Any queue of pending actions. All six require knowledge Agency V2 does not have, and drawing them would make the interface lie on the model's behalf.

The question

If nobody thought of Mike as an app, what would using it feel like?

It would feel like the computer started paying attention. You would never launch anything and there would be nothing to arrive at — you'd be in the editor, say what you wanted, and a caret would appear at the edge of the screen where you were already looking. It would do the thing, or tell you plainly that it couldn't, and then it would leave.

You would open Home the way you open a drawer: not to use Mike, but to see what the two of you have accumulated — what it did last week, what it believes about you, what it is allowed to touch. And the strongest proof it worked would be that you stopped noticing you were using software at all: only that the machine, lately, is paying attention.
